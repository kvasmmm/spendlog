# SpendLog

Персональное mobile-first приложение для покупок, цен и долгов. React + TypeScript + Vite + Tailwind + Recharts; FastAPI + SQLAlchemy + Alembic; SQLite; Docker Compose. Интерфейс на русском, валюта KRW, время Asia/Seoul.

## Быстрый запуск

Нужны Docker Engine / Docker Desktop с Compose v2.

```bash
cp .env.example .env
```

В `.env` задайте `APP_PASSWORD` — собственный пароль от 12 символов. Для локального запуска оставьте остальные значения как в примере.

```bash
docker compose up -d --build
```

Откройте **http://localhost:8080** и войдите с этим паролем. Миграция применяется автоматически перед запуском API. Пустая база создаётся без демонстрационных покупок.

```bash
docker compose logs -f backend
docker compose down
```

Обычный `down` сохраняет данные в Docker volume `spendlog_data`. **`docker compose down -v` удаляет базу** — не используйте его для остановки.

## Доступ с телефона и HTTPS для отладки

В одной Wi-Fi сети откройте `http://IP-компьютера:8080`. В Compose по умолчанию `WEB_BIND=0.0.0.0`, поэтому порт доступен в локальной сети. Можно ограничить его через `.env`: `WEB_BIND=127.0.0.1` (удобно при работе через туннель).

Для HTTPS на телефоне без своего домена запустите на компьютере:

```bash
cloudflared tunnel --url http://127.0.0.1:8080
```

Или без установки cloudflared:

```bash
docker run --rm --network host cloudflare/cloudflared:latest tunnel --url http://127.0.0.1:8080
```

Откройте выданную ссылку `https://….trycloudflare.com` в Safari. Она временная и доступна из интернета; оставьте приложение защищённым паролем. Wi-Fi не обязан быть общим. Для режима исключительно HTTPS задайте `COOKIE_SECURE=true` и пересоздайте backend. Самому nginx локальный TLS при туннеле не нужен. [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## iPhone, постоянный HTTPS и установка PWA

Для постоянного публичного адреса можно использовать сервер с доменом или именованный Cloudflare Tunnel. Встроенный хостинг Sites не запускает этот Python/Docker-проект; он предназначен для вашего VPS или другого Docker-хоста.

1. Направьте DNS домена на сервер, откройте входящие TCP 80/443 и при необходимости UDP 443.
2. Скопируйте проект на сервер. В `.env` задайте надёжный `APP_PASSWORD` и `DOMAIN=spendlog.example.com` (замените своим доменом).
3. Запустите:

```bash
docker compose -f compose.yaml -f compose.https.yaml up -d --build
```

Caddy получает TLS-сертификат автоматически. HTTPS-конфигурация принудительно включает Secure для cookie. Backend не публикует свой порт; Чтобы nginx оставался доступен только на сервере, задайте `WEB_BIND=127.0.0.1`; по умолчанию разрешён доступ из локальной сети.

Откройте `https://ваш-домен` в Safari → «Поделиться» → «На экран Домой». Разрешите камеру при первом сканировании. Для камеры нужен HTTPS (исключение — localhost на том же устройстве). `localhost` на iPhone не означает ваш компьютер.

PWA включает manifest, PNG-иконки, standalone-режим и service worker со страницей отсутствия сети. **Офлайн-записи и фоновая синхронизация не реализованы**: сохранение требует связи с API. Незавершённая корзина сохраняется в localStorage данного браузера и адреса, включая ключ защиты от повторов. Старый sessionStorage-черновик подхватывается. При запрете постоянного хранилища используется sessionStorage и показывается предупреждение. Это не офлайн-синхронизация; не добавленная в чек текущая строка товара отдельно не сохраняется. HTTP, HTTPS и разные домены имеют разные хранилища. Выход из аккаунта очищает черновик. Личные данные не кешируются service worker.

## Основные сценарии

### Товар по штрихкоду

Для товаров со штрихкодом откройте «Каталог» → «По штрихкоду». «Новая покупка» → камера или ручной штрихкод → «Найти». Для товара из личного каталога подставятся название, категория и последняя фактически сохранённая цена. Если локального товара нет, выполняется поиск по общему справочнику `barcodes`: подставляются только название и категория, цену нужно ввести. При добавлении позиции создаётся личный Product. Новый неизвестный штрихкод при добавлении товара атомарно попадает в оба каталога. Проверьте цену: в другом магазине она может отличаться. Для неизвестного штрихкода заполните название, категорию и цену → «В чек». Товар появится в каталоге.

Сканер: ZXing, в том числе распространённые EAN/UPC и Code 128. При отказе камеры всегда доступен ручной ввод. Кнопка «Каталог» позволяет искать товар по названию. Нажатие Enter в поле штрихкода выполняет поиск.

### Меню заведений: тонкатсу, чикенмайо и другие позиции

«Каталог» → **«Моё меню»** → **«Карточка»**: укажите точное название заведения, блюдо, цену за порцию и категорию. Штрихкод не нужен; меню хранится отдельно от общего справочника штрихкодов. Для разных заведений используются разные карточки. Цена карточки — подсказка для новых чеков, фактические цены и категории остаются в исторических Item.

При записи покупки можно:

- открыть карточку через «В покупку»;
- выбрать заведение и нажать блюдо в блоке «Меню заведения»;
- найти блюдо через «Каталог» внутри формы;
- ввести новую позицию и включить «Сохранить блюдо / товар в меню заведения».

После выбора укажите количество и добавьте позицию кнопкой «В чек». Например, тонкатсу × 3 и чикенмайо × 6 остаются двумя позициями с отдельными ценами и суммарным количеством. Изменение карточки меню не меняет старые чеки. Карточку с историей нельзя перенести в другое заведение; для другого места создайте новую.

**Разобрать банковское списание позже:** «Банк» → раскройте «Банковские операции» → у отрицательной операции нажмите **«Добавить блюда / товары»**. Место, время и итог взяты из банка; введите блюда и количество. Сумма позиций должна точно совпасть со списанием. Создание чека и связь с платежом выполняются атомарно, с Idempotency-Key и проверкой версии; второго списания не остаётся. Можно указать свою долю и долг друга. У уже связанной операции кнопка **«Изменить позиции»** открывает чек: состав можно исправлять с сохранением общей банковской суммы и времени оплаты. Если есть возвраты долга, действует прежний запрет изменения до их исправления.

На «Обзоре» появился блок **«Что покупал в каждом месте»** за выбранный финансовый месяц. Выберите заведение и раскройте его: видны товары/блюда, количество и личные расходы. Банковская сумма без позиций показывается отдельно — приложение не угадывает, какое блюдо было куплено. Количество относится ко всему чеку; при разделённой покупке деньги показываются по личной доле, а не как доказательство того, кто съел каждую порцию.

### Категории расходов

Добавлены «Еда вне дома», «Магазины у дома», «Обязательные траты», «Страховка», «Связь и интернет», «Подписки», «Здоровье и клиники», «Транспорт», «Жильё» и другие. Старые категории сохранены для совместимости, история автоматически не переклассифицируется.

В банковском предпросмотре категорию можно назначить всей группе обычных новых списаний или одной строке. После импорта она меняется у несвязанной операции в «Банковских операциях». Категория банковской строки — запасная классификация: после добавления товаров расходы берутся из категорий позиций чека. Поэтому GS25 может быть магазином у дома, а конкретные продукты и напитки — иметь собственные категории. Поступления, переводы и займы не становятся расходом от выбора категории.

### Ручной расход и несколько товаров

Для ресторана, транспорта, PC Café, услуги или подписки оставьте штрихкод пустым и добавьте одну позицию с названием и суммой. Для смешанной покупки добавьте несколько позиций с собственными категориями. Количество — целое число; весовой товар можно внести одной позицией с итоговой стоимостью.

Укажите магазин, дату и сумму на чеке. По умолчанию сумма равна сумме позиций, её можно заменить значением с бумажного чека. Расхождение блокирует сохранение. Для скидок и акций указывайте фактически уплаченную цену позиции; отдельного механизма промокодов/отрицательных скидочных строк нет.

Карандаш в корзине открывает позицию в форме. Измените её и нажмите «Обновить позицию» перед сохранением покупки. До подтверждения исходная позиция остаётся в корзине.

### Чужая доля и возмещение

В покупке включите «Часть суммы мне вернут», задайте свою долю и человека/организацию. В MVP один получатель долга на чек. Выберите «Чужая доля» или «Возмещение расходов». Вкладка «Долги» показывает остаток; возвраты могут быть частичными.

Пример: оплачено 40 000 ₩, моя доля 20 000 ₩:

- личные расходы: 20 000 ₩;
- исходящий денежный поток: 40 000 ₩;
- долг друга: 20 000 ₩.

После возврата 20 000 ₩ личные расходы остаются 20 000 ₩, доход остаётся 0, чистый денежный поток становится −20 000 ₩. Возмещение работает так же: ожидаемая компенсируемая доля исключается из личного потребления уже при записи покупки; фактическое списание видно в денежном потоке. Это учёт ожидаемых возмещений, не подтверждение выплаты организацией.

Своя доля распределяется по категориям позиций пропорционально их сумме. Остатки целых вон распределяются методом наибольших остатков. Ручное назначение владельца каждой позиции и несколько друзей на одном чеке — вне этого MVP.

### Доходы и займы

«Операции» → «Доход / заём». Поддерживаются обычный доход, выданный и полученный заём. Полученный заём не увеличивает показатель доходов; выданный заём и его погашение не увеличивают потребительские расходы. Все движения отражаются в денежном потоке.

### Исправления

Покупки, доходы, займы и возвраты можно редактировать и удалять во вкладке «Операции». Редактирование покупки атомарно заменяет связанные позиции, платёж и долг. Если уже есть возвраты, сначала исправьте или удалите их: приложение не удаляет их молча вместе с покупкой/займом. Версия записи защищает от перезаписи устаревшей формы.

Изменения названия/категории в каталоге не меняют старые чеки. Для исправления исторической классификации редактируйте саму покупку.

### Аналитика и правила

- Финансовый месяц по умолчанию: 22-е — 21-е; начало можно выбрать с 1-го по 28-е.
- Доходы, личные расходы, денежный поток, поступления/списания.
- Категории и магазины, дневная/недельная динамика, последние 6 финансовых месяцев.
- Частые товары по количеству; история фактических цен с магазином.
- Число покупок, средняя личная доля чека, средние расходы за день.
- Сравнение выбранного периода с **полным** предыдущим периодом; неполные месяцы не приводятся к одинаковому количеству дней.
- Общий и категорийные лимиты. Лимиты помогают следить за расходами, не блокируют ввод.
- Правила по подстроке названия для новых ручных позиций. Категория известного товара приоритетнее правила. При нескольких совпадениях используется первое правило в возвращаемом API порядке (по ID); лучше избегать пересекающихся правил.

Категории товаров определяют аналитику; GS25 не автоматически приравнивается к питанию. В интерфейсе нет предзаполненных реальных расходов пользователя.

## Банковские выписки iM Bank: предпросмотр и подтверждение

Новая вкладка **«Банк»** принимает текстовую PDF до 5 MB. Парсер написан после изучения предоставленного файла «거래내역조회»: счёт и период в заголовке, номер строки NO, время до секунды, списание, зачисление, остаток после операции, описание. В реальном примере 145 строк; проверяется полная нумерация и непрерывная цепочка остатков между всеми соседями. Работают прямой/обратный порядок выгрузки и перестановка физических строк при сохранении номеров. Неизвестный формат, потерянная страница, некорректные суммы или разрыв остатков отменяют предпросмотр целиком. OCR, защищённые PDF, произвольные банковские CSV/XLS не поддерживаются. Для извлечения текста нужен `pdftotext` (в Docker добавлен `poppler-utils`).

1. Загрузите PDF. До подтверждения финансовые записи не создаются; сохраняется только история предпросмотра.
2. Проверьте сводку по названиям: например, филиалы GS25 собраны в одну раскрывающуюся группу с количеством и общей суммой. Списания и поступления показываются раздельно. Фильтр «Нужно решить» выделяет неоднозначные строки и кандидатов сверки; обычные новые строки и подтверждённые повторы уже подготовлены. Поиск работает по исходным названиям и названию группы. Группировка относится только к отображению и не объединяет банковские операции.
3. Для обычных новых строк группы можно одним действием выбрать расходы, переводы или явно отметить поступления доходами. Групповые действия не затрагивают повторы, неоднозначные строки и строки с кандидатами сверки. Отдельную строку можно раскрыть и изменить вручную. У каждой спорной строки выберите: отдельная операция, повтор конкретной банковской записи либо связь с конкретным чеком. Можно отметить списание/поступление как перевод без расхода/дохода; обычный доход выбирается только явно.
4. Подтвердите все строки одной транзакцией. Ошибка любой строки отменяет все изменения. Параллельные запросы сериализуются, Idempotency-Key защищает повтор подтверждения. Уже подтверждённая выписка повторно ничего не добавляет.

**Защита от дублей.** NO — номер строки выгрузки, не банковский ID. В изученном PDF стабильного ID нет. Идентичный нормализованный состав строк одного счёта имеет тот же semantic hash независимо от номера страницы, периода заголовка, пробелов, файла и порядка строк. Для пересекающихся файлов совпадение включает счёт, направление, точное время, сумму, остаток и описание; автоматическая пометка «повтор» дополнительно требует уникального совпадающего соседнего движения и сходящихся остатков. Одиночное совпадение, несколько одинаковых кандидатов и изменённая строка считаются неоднозначными. Две покупки одной суммы в одном магазине сохраняются отдельно. Изменённые сумма/направление/время не могут быть молча пропущены как повтор; автоматическое исправление ранее импортированного движения не реализовано. Это осторожное сопоставление по доступным свидетельствам, а не гарантия банковского идентификатора.

После другого подтверждения старый предпросмотр получает 409: загрузите PDF снова, чтобы пересчитать кандидатов. История хранит parser version, SHA-256 файла, хеш и маску счёта, исходный извлечённый текст, каждую исходную строку и принятое решение. Исходный PDF не сохраняется в БД. Для будущего формата с банковским ID предусмотрены поле `bank_id` и уникальность `(bank, account_key, bank_id)`; текущий PDF его не заполняет.

### Модель расчёта и сверка

| Запись | Личные расходы | Доход | Денежный поток |
|---|---:|---:|---:|
| Ручной или связанный чек | `Purchase.own_amount` | 0 | один `Payment.amount` |
| Несвязанный `bank_unclassified`, списание | полная сумма временно | 0 | подписанная сумма |
| Несвязанный `bank_unclassified`, поступление | 0 | 0 | подписанная сумма |
| `bank_transfer` | 0 | 0 | подписанная сумма |
| Явно выбранный `income` | 0 | сумма | сумма |
| Заём / возврат основного долга | 0 | 0 | подписанная сумма |

Несвязанные списания видны в выбранной категории, а при её отсутствии — в «Банк: без категории» и в общем показателе расходов, включая дневную/месячную динамику; dashboard показывает отдельное предупреждение. Средний чек относится только к реальным Purchase. Датой потребления остаётся время покупки, датой движения денег — фактическое время банка, в том числе если они попали по разные стороны 21/22 числа.

Сверка предлагает ручные покупки той же полной суммы в пределах ±10 минут, учитывает сходство магазина, но сама ничего не связывает. Во вкладке банковских операций можно вручную выбрать и более далёкий по времени чек той же суммы. При связи сохраняется исходный ручной Payment и его `created_at`, его `occurred_at` получает время банка, исходный отдельный банковский Payment удаляется, `BankTransaction` ссылается на сохранённый платёж. Purchase и её позиции не переписываются; у Purchase сохраняются `occurred_at` и `created_at`. Личная доля и долг не меняются. Конкурирующая связь и устаревшая версия отклоняются.

«Отменить связь» восстанавливает время ручного платежа из чека и отдельный неклассифицированный банковский Payment. После этого оба несопоставленных движения снова видны до повторной сверки; приложение предупреждает об этом. Удаление связанного чека требует отменить связь — банковское происхождение не удаляется каскадом. Состав связанного чека можно редактировать без отмены связи при сохранении банковской суммы; исходный Payment и его даты сохраняются. Импортированные движения изменяются во вкладке «Банк», а не через форму ручного дохода.

Автоматического объединения банковских строк с вручную записанными займами и возвратами долгов пока нет. Такие строки не становятся доходом автоматически, но требуют отдельной сверки; не записывайте одно движение повторно вручную. Разделение одного банковского платежа между несколькими чеками, валюты кроме KRW и автоматическое исправление банковских сумм пока не поддерживаются.

### Общий справочник штрихкодов

`barcodes` хранит только штрихкод, название и категорию; `products` — личный каталог, `items` — исторические снимки цен и категорий. Изменение личного товара не меняет общий справочник и старые чеки. При обновлении базы миграция копирует существующие товары в `barcodes`, сохраняя их ID и все связи. Общие записи пока добавляет единственный авторизованный владелец при создании нового штрихкода. Цены, магазины, долги и покупки в общий справочник не попадают.

Это отдельная таблица в той же SQL-базе, без нового сервера или микросервиса. Мультипользовательская авторизация и модерация общего каталога пока не реализованы; перед её добавлением потребуются владельцы личных сущностей и права на публикацию общих записей.

## Сохранность и перенос данных

В настройках доступны **полный JSON и полный CSV**. Оба сохраняют общий и личный каталоги, меню заведений, категории банковских расходов, магазины, позиции, покупки, платежи, долги, настройки, правила, ключи защиты от повторов и полную историю банковских импортов со связями и исходным текстом. Пароли и сессии в экспорт не входят.

CSV имеет две колонки: `table,record_json`. Это переносимый **архивный CSV со всеми связями**, не плоский банковский отчёт. JSON — предпочтительный формат ручного резервирования. Импорт произвольного банковского CSV не поддерживается; PDF банка загружается отдельным процессом через вкладку «Банк».

Импорт:

- до 10 MB, формат SpendLog v3 / KRW; старые JSON/CSV v1 и v2 также принимаются;
- выполняется одной транзакцией;
- одинаковые записи с тем же ID пропускаются;
- конфликт одного ID с другим содержимым отменяет весь импорт;
- проверяются связи, суммы покупок, направления движений и остатки долгов;
- не очищает и не перезаписывает существующую базу.

Для восстановления более старой версии поверх изменённых данных используйте **новую пустую базу/новый volume**, затем импортируйте копию. Предварительно сохраните текущую базу. Не удаляйте существующую базу ради пробного импорта.

### Снимок SQLite на сервере

JSON удобен для переноса, а SQLite Online Backup сохраняет всю базу, включая сессии и номер миграции. Не копируйте только `.db` во время работы: часть записей может находиться в WAL.

```bash
docker compose exec -T backend python < scripts/backup.py
```

Команда печатает путь `/data/backups/spendlog-YYYYMMDD-HHMMSS.db`. Скопируйте указанный файл с сервера:

```bash
mkdir -p backups
docker compose cp backend:/data/backups/ИМЯ_ФАЙЛА.db ./backups/
```

Храните копии вне того же сервера. Периодический backup можно запускать вашим cron. База и экспорт содержат личную финансовую информацию; храните их приватно. Автоматическая внешняя ротация резервных копий в MVP не включена.

## Разработка без Docker

Требуются Python 3.12, Node.js 22+ и `pdftotext` из poppler-utils.

```bash
cd backend
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export APP_PASSWORD='replace-with-your-own-long-password'
export COOKIE_SECURE=false

alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес Vite (обычно http://localhost:5173). Vite проксирует `/api` на `127.0.0.1:8000`. API-схема: http://localhost:8000/docs. Для изменяющих API-запросов обязателен заголовок `X-SpendLog: 1`; для создания покупки/платежа/возврата — также уникальный `Idempotency-Key`. В Swagger сначала выполните login с `X-SpendLog` через свой HTTP-клиент либо используйте cookie с тем же origin.

```bash
# Из backend:

alembic check

# Из frontend:
npm run test:helpers
npm run build
```

## Архитектура и финансовые инварианты

```text
frontend/             React UI, ZXing scanner, Recharts, manifest + service worker
backend/app/models.py SQLAlchemy tables, SQLite connection settings
backend/app/schemas.py Pydantic validation (integer KRW, timezone-aware dates)
backend/app/main.py    API, authentication, atomic ledger mutations, reports, backup
backend/alembic/      versioned schema migration
backend/tests/        critical ledger and API tests
compose.yaml          FastAPI + nginx, persistent volume
compose.https.yaml    optional Caddy TLS gateway
scripts/backup.py     SQLite Online Backup
```

- `MenuProduct` хранит частную карточку блюда/услуги, заведение и цену по умолчанию; `Item.menu_product_id` связывает историческую позицию с карточкой.
- `Barcode` хранит общие метаданные без цен.
- `Product` хранит штрихкод/название/категорию, **не текущую цену**.
- `Item` хранит снимок названия, категории, цены, количества и личной доли.
- `Purchase` объединяет позиции, магазин, время фактической покупки и отдельное время создания записи.
- `Payment.purchase_id` уникален: в MVP один исходящий платёж на покупку. Нулевая покупка не создаёт фиктивного движения денег.
- `Debt` связан с покупкой или исходным займом; возвраты — отдельные `Payment(kind=settlement)`.
- Личные расходы — `Purchase.own_amount` плюс только несвязанные неклассифицированные банковские списания. Связанные платежи не прибавляются второй раз; правила описаны выше.
- `Payment.created_at` хранит время создания записи отдельно от `occurred_at`. При миграции старых платежей фактическое время создания неизвестно: для них заполняется прежнее `occurred_at`.
- `income` — только явно записанный доход. Возвраты и займы — другие типы.
- Целые суммы KRW; для распределения денег не используется float. Средние значения на dashboard округляются только для отображения.
- Даты хранятся в каноническом UTC, границы периодов считаются в Asia/Seoul.
- Проверка суммы чека, отсутствие переплаты долга, запрет возврата до возникновения долга.
- Повтор одного `Idempotency-Key` с тем же запросом возвращает прежний результат. Изменённый запрос с тем же ключом получает 409. После удаления операции старый ключ всё ещё не создаёт её повторно.
- SQLite: foreign keys, WAL, busy timeout, BEGIN IMMEDIATE. Для персонального приложения операции сериализуются, включая чтения, чтобы snapshot/export оставались согласованными.
- Транзакция фиксируется до HTTP-ответа. Ошибка в любом шаге откатывает операцию.
- Персональный пароль в окружении, HttpOnly/SameSite=Strict cookie, CSRF-header, ограничение попыток входа. Сервер работает одним worker; сессии живут 30 дней. Смена пароля сама по себе не отзывает ранее выданные сессии — для отзыва всех выполните `DELETE FROM sessions` в своей базе после остановки приложения/через админский скрипт.

### Переход на PostgreSQL

SQLAlchemy и миграция используют переносимые типы; драйвер psycopg включён. Укажите `DATABASE_URL=postgresql+psycopg://...`, примените `alembic upgrade head` к пустой PostgreSQL и импортируйте полный JSON из SQLite. Для согласованных персональных операций предусмотрен PostgreSQL advisory transaction lock. Сам PostgreSQL-сервер не включён в Compose; E2E на PostgreSQL не выполнялся. Перед переключением проверьте импорт и суммы в отдельной среде. Простая смена URL не переносит данные автоматически.

## Границы MVP

В исходном MVP реализованы: каталог, камера с ручным fallback, корзина, история, расходы/доходы, долги, dashboard, редактирование/удаление, JSON/CSV, PWA-оболочка.

Добавлены PDF-импорт iM Bank с предпросмотром, банковское происхождение, консервативное сопоставление дублей и ручная обратимая сверка с чеками. Эти функции требуют приёмки на реальном устройстве и контейнерной сборки с закреплёнными зависимостями.

Пока не реализованы: OCR, KakaoPay, внешние базы штрихкодов, автоматическое сопоставление займов/возвратов, автоматические внешние резервные копии с ротацией, детекция подписок и аномалий, рекомендации.

Это один персональный аккаунт. Нет нескольких пользователей, нескольких валют, нескольких плательщиков на одном чеке, инвентарного учёта и офлайн-синхронизации. Для возврата товара магазину отдельного сценария нет; это не то же самое, что возврат долга.
